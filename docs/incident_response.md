# Incident Response Playbook: Observability Stack

This document outlines the standard operating procedures (SOPs) for responding to alerts generated by our Prometheus/Grafana/Loki stack.

## 🚨 Alert: High CPU / Memory Usage
**Symptom:** `app_memory_usage_bytes` > 800MB or CPU spikes observed in Grafana.

### Triage Steps:
1. **Check Dashboard:** Open the "App Overview" dashboard in Grafana.
2. **Identify Patterns:** Is it a steady climb (Memory Leak) or a sudden spike (Traffic burst)?
3. **Check Logs:** 
   - Query Loki: `{job="flask_app"}` 
   - Look for specific high-latency requests that might be resource-intensive.
4. **Remediation:**
   - If a specific endpoint is causing spikes, consider rate-limiting.
   - Restart the service if memory usage is critical.

## 🚨 Alert: Service Downtime (Health Check Fail)
**Symptom:** `service_up{service="app"}` == 0.

### Triage Steps:
1. **Check Connectivity:** Try to `curl http://localhost:5000/health` manually.
2. **Check Logs:** Look for "Panic" or "Exception" logs in Loki.
   - Query: `{job="flask_app"} |= "Exception"`
3. **Check Infrastructure:** Is the Docker container running? `docker ps`.
4. **Remediation:**
   - Restart the container: `docker-compose restart app`.
   - Check recent code changes if the crash is persistent.

## 🚨 Alert: Potential Brute Force Attack
**Symptom:** High frequency of 401 Unauthorized status codes on `/login`.

### Triage Steps:
1. **Verify in Loki:**
   - Query: `count_over_time({job="flask_app"} |= "auth_failure" [1m])`
2. **Identify IP:** 
   - Check the `ip` label in logs to see if it's a single source.
3. **Remediation:**
   - Block the offending IP at the firewall/load balancer level.
   - Investigate if the compromised account exists.
